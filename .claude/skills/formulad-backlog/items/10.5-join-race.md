# 10.5 — Join a race

From My Racer: enter a name, get added to the race, and hold the claim. This is
the cold-start path for a player who isn't in the race yet — and the only path
when the race has no racers at all.

**Depends on:** item 10.

## UI

In the My Racer subview, alongside the racer list — and **in place of it** when
the list is empty. An empty racer list with no way to act is a dead end, and per
the paradigm this is the first screen a player sees.

Name field, one button. Nothing else: the app models one piece of player data
today.

## The mutation

New `lib/race.ts` function:

```ts
joinRace(raceId, name, uid, who)
```

In one transaction:

- Derive the id with `playerId(name)` from `lib/setup.ts` — ids are name slugs so
  the same human is stable across races.
- `set` the `players/{id}` doc with `{ merge: true }`, matching `createRace`, so a
  returning player's record isn't clobbered.
- Create `participants/{id}` with `startPosition` at the back of the grid,
  `lapsCompleted: 0`, `finalPosition: null`, `dnf: false`, `claimedBy: uid`.
- Append the id to `positionOrder`.
- Append a `playerJoined` event; add it to the union.

## Do not touch `roundOrder`

A player joining mid-race enters `positionOrder` only. They start taking turns
**next round**, when `roundOrder` is snapshotted from `positionOrder` at rollover.

This is the same rule as an overtake: mid-round changes to standings affect the
next round, never the one in progress. Splicing a new car into a round already
underway would break the `turnIndex`/`alreadyMoved` arithmetic in the views and
give the joiner a turn out of nowhere.

## Guards

- Refuse if `race.status === "complete"`.
- Refuse a duplicate `playerId` in this race — surface it as "that name is
  already racing", and point them at the racer list to claim it instead. This is
  the likely path for someone who arrives, gets added by the commissioner, and
  then opens the link themselves.
- Refuse an empty or whitespace-only name, and one that slugs to an empty string
  (`playerId("...")` returns `""`).

## Interaction with item 6

Item 6 locks roster **editing** once a race starts but deliberately leaves
**adding** open — this is that exception. If item 6 adopted the
`scheduled` → `live` flow, joining works in both states; only removal locks.

## Acceptance

- Joining an empty race creates the player and claims them.
- Joining mid-race adds to the back of `positionOrder` and does not disturb the
  round in progress; the joiner takes a turn from the next round.
- Duplicate names are refused with a message that points at claiming instead.
- Cannot join a complete race.
- Smoke coverage for a mid-race join, asserting `roundOrder` is unchanged.
